# 图层系统重构 — 设计确认

状态：**待确认** ｜ 影响范围：`core` / `bridge` / `QML` 三层 ｜ 前置：无

---

## 1. 目标

一句话：把当前**并行的三套模型**（背景 base、图层 layers、标记 marks）收敛成**一套有序的 `Layer` 列表**，
在统一模型上补齐图层管理能力（新建 / 复制 / 合并 / 对齐分布 / 多选批量），并重做图层面板（缩略图 + 信息）。

> 关键前提：本项目**没有工程文件格式**（保存 = `doc.flatten()` 编码成 PNG/JPEG/WebP），
> 因此模型改动**没有向后兼容负担**，不需要写文件版本迁移。这是敢做结构重构的最大理由。

---

## 2. 现状诊断

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| 1 | 背景不是图层：`base: RgbaImage` 独立存在 | `core/document/mod.rs:7` | 所有通用能力都要写两套分支（合成、吸附、调色、擦除、导出） |
| 2 | 背景状态用 4 个并列布尔标志 | `doc.base_deleted` / `base_hidden` / `base_converted` / `session.base_locked` | 状态组合不封闭，`base_converted=true` 后 `base_*` 语义全部失效，只能靠阅读代码判断 |
| 3 | 面板为背景造了一行合成行 `i:-1` | `bridge/session.rs::layers_json`、`LayerPanel.qml` | QML 里到处 `isBase` / `bd` / `row.i === -1` 特判；眼睛与锁走两套 qinvokable |
| 4 | "解锁背景"是个**隐式迁移** | `set_base_locked(false)` → `convert_base_to_layer()` | 点一下锁图标就永久改变文档结构、索引整体 +1、选中被清空；用户不知道发生了什么 |
| 5 | 标记是独立数组，恒画在最上层 | `doc.marks: Vec<Mark>`、`flatten()` 末尾追加 | 图层与标记无法互相穿插；面板分两个区，两套选中态（`selected_layer` / `selected_mark`）、两套删除与可见性逻辑 |
| 6 | 两套索引：doc 升序 vs 面板降序 | `LayerPanel.qml` 的 `docLen-1-p` | 排序、插入、多选都要反复换算，`nonBaseRowCount()` 专为此存在 |
| 7 | 锁定不入历史 | `set_layer_locked` 直接改字段 + `refresh_layers_only()` | 误锁/误解锁撤不回来（可见性、不透明度都入历史，唯独锁定例外） |
| 8 | 面板无缩略图 | `LayerPanel.qml` 230px / 行高 34 | 只能靠名字认层；`layers_json` 里的 `x/y/w/h` 只有数字，没有视觉 |
| 9 | 缺常用命令 | 右键菜单仅"旋转角度 / 删除 / 导出 PNG" | 无新建空层、无复制、无合并、无对齐分布；`copy_selected_layer` 只进剪贴板（Ctrl+V 粘贴），不是"原地复制" |
| 10 | 无多选 | `selected_layer: i32` 单值 | 批量隐藏 / 锁定 / 删除 / 对齐全部做不到 |

## 3. 目标模型

### 3.1 数据结构

```rust
pub type LayerId = u32;

/// 图层内容：位图 or 矢量标记。两者共享外层的可见/锁定/不透明度/顺序/名字。
pub enum LayerContent {
    Raster {
        image: RgbaImage,
        offset: (i32, i32),
        /// 非破坏性变换（P0-1 已有，语义不变）
        transform: Option<LayerTransform>,
    },
    Mark(Mark),
}

pub struct Layer {
    pub id: LayerId,          // 稳定 id：多选集合、缩略图缓存、日志都用它
    pub name: String,
    pub visible: bool,
    pub locked: bool,
    pub opacity: f32,         // 标记也获得不透明度
    pub background: bool,     // 仅 layers[0] 可为 true（默认 locked）
    pub content: LayerContent,
}

pub struct Document {
    pub canvas: Size,
    pub view: Rect,           // 裁剪窗口，保留：裁剪仍是 O(1) 平移视窗
    pub layers: Vec<Layer>,   // ★ 索引 0 = 最底（背景），len-1 = 最顶
    pub next_layer_id: LayerId,
    // 删除：base / base_deleted / base_hidden / base_converted / marks
    // 保留：selection / edit_epoch / next_layer_seq / history / source
}
```

### 3.2 不变量

1. `layers` 永不为空：背景层恒存在（删背景 = 清空其像素，见 D1）。
2. `layers[0].background == true` 且是唯一的；`background` 层必须是 `Raster`。
3. 渲染顺序 = `layers` 数组顺序（0 → len-1 依次合成）。**标记不再天然置顶**。
4. 所有可见性 / 锁定 / 不透明度 / 名字变更走同一组 `EditOp`，全部入历史。
5. 任何写像素的 op 前仍需 `ensure_baked()`（现有契约不变）。

### 3.3 渲染单点收敛

```rust
impl Document {
    /// 唯一合成入口：composite_pixel / flatten / GPU 快路径 / 缩略图 全部走这里。
    pub fn composite_pixel(&self, x: i32, y: i32) -> Rgba<u8> {
        let mut out = [0, 0, 0, 0];
        for layer in &self.layers {
            if !layer.visible || layer.opacity <= 0.0 { continue; }
            match &layer.content {
                LayerContent::Raster { image, offset, .. } => blend_raster(&mut out, image, *offset, layer.opacity, x, y),
                LayerContent::Mark(m) => { /* 标记按 opacity 混合 */ }
            }
        }
        Rgba(out)
    }
}
```

现状 `composite_pixel` 里"先取 base 像素再叠 layers"的特判、`flatten` 末尾"标记恒置顶"的追加，两条都消失。
`view`（裁剪窗口）继续在坐标换算层生效，不进合成循环。

## 4. 关键设计决策

### D1 · 背景归一（推荐：`layers[0]` + `background` 标志）
- 旧 `base_deleted`：等价于 `layers[0].image` 全透明 → **不再需要标志**（删除 = 清空像素，一条 op）。
- 旧 `base_hidden`：等价于 `!layers[0].visible`。
- 旧 `base_converted`：等价于 `layers[0].locked == false`（标志仍为 background，只是可移动）。
- 旧 `session.base_locked` 删除，改用 `doc.layers[0].locked`（并且**入历史**）。
- "解锁背景"不再是隐式迁移：点锁图标 = 一条 `SetLocked`，世界照旧，只是可拖动。

> 备选（不推荐）：保留 `base` 字段，只在 UI 层做视图适配 —— 债继续累积，等于没整理。

### D2 · 标记并入图层（推荐：是，但**新标记默认插到最顶**）
- 迁移：旧文档里 `marks[0..]` 按原顺序追加到 `layers` 末尾，视觉结果与原"恒置顶"**完全一致**。
- 之后用户可以把标记拖到某个位图图层下面（这是新能力）；吸附、删除、可见性、锁定全部复用图层逻辑。
- 代价：`marks.rs`（553 行）里所有 `doc.marks.get(i)` 改为按 `LayerId` 找；`marks_json` / `selected_mark` 保留为"标记子集的视图"，避免大面积改 QML 交互代码。
- 注意：`MarkBar.qml` 的"当前标记工具"、`SelectionViz` 的标记选框都按 id 走，不再按数组下标。

### D3 · 历史 op 继续用 `index`，UI 选择集合用 `id`（推荐）
- 理由：undo/redo 是按栈顺序 apply/revert，栈内 index 天然自洽；改成 id 则需要每个 op 查表，且`RemoveLayer` 撤销后 id 重复等边界更复杂。
- 多选集合、缩略图缓存键、日志必须用稳定 `id`（index 会被插入/排序打乱）。
- bridge 入口负责 `id → index` 解析，解析失败直接忽略（防 stale 集合）。

### D4 · GPU 快路径（Tier 1 仅移动）加限制条件
- 现状：`gpu_begin` 生成"隐藏活动层的全幅静态图 + 活动层位图"，叠加后活动层被临时提到最前。
- 统一模型后标记可在中间，问题会更明显。**方案：仅当活动层是 `layers[len-1]`（最顶层）时启用 GPU 快路径，否则回退 CPU**。
  判定一行代码，行为可预测；后续如需中间层加速，再加"上段纹理"（第三张）。
- 现有回归 `probe_gpu_overlay.py`（MAD 断言屏幕像素）继续作为验收。

### D5 · 缩略图（推荐：`QQuickImageProvider`）
- URL 形如 `image://layer-thumb/<id>?e=<edit_epoch>`；provider 内部按 `(id, epoch, 48px)` 缓存 PNG。
- 备选：bridge 返回 base64 字符串属性 —— 100 层 × 20KB 会撑爆属性绑定，不推荐。
- 缩略图绘制：透明底棋盘格 + 内容 contain 缩放；`Mark` 层用 `mark.draw` 画到临时小图。
- 缓存失效键：`edit_epoch`（任何提交/撤销/重做都变）；纯 live 拖动不变（符合现有预览缓存策略）。

### D6 · 多选交互（推荐：批量属性，拖动只动主选中）
- 点击 = 单选；`Ctrl+点击` = 切换；`Shift+点击` = 区间（面板显示顺序）。
- `selected_layer` 保留为 **active（主选中）**，新增 `selected_layer_ids: Vec<LayerId>`。
- 批量化：显示/隐藏、锁定、不透明度、删除、对齐、分布、合并（选中项参与）。
- **拖动/缩放/旋转仍只作用于 active 层**（多框手势是另一个量级的工作，本期不做，明确写进 UI 提示）。
- 画布选框只画 active 层。

### D7 · 撤销粒度
- 新增 `SetLocked { index, from, to }`。
- 新增 `SetLayersOffset { entries: Vec<(usize, (i32,i32), (i32,i32))> }`（对齐/分布一条历史，而不是 N 条）。
- 新增 `UpdateLayerAttrs { ids, from, to }`（批量可见/锁定/不透明度）。
- `History::push` 现有"连续 `SelectionOptions` 合并"的机制抄一份给 `SetOpacity` / `SetLocked` 的同 index 连续变更（拖动滑杆不塞 N 条）。

### D8 · 合并与栅格化
- `DuplicateLayer { index }`：`AddLayer`，新 id，插到源层上方，名字加" 副本"。
- `MergeDown { index }`：下方层必须是 `Raster`；上方是 `Raster` 按其 offset/opacity/transform 合成；上方是 `Mark` 先**栅格化**（画进临时图、取 AABB）再合成。结果保留下层 id/name/位置。一条 op（存前后两层）。
- `MergeVisible` / `FlattenLayerStack`：快照式一条 op（`DocumentSnapshot` 前后），走现有 `restore()`。
- `RasterizeMark { index }`：单独命令，标记 → 位图图层（右键"栅格化"）。

### D9 · 对齐 / 分布
- 新增 `core/align.rs` 纯函数：`align(rects, mode) -> Vec<(dx, dy)>`、`distribute(rects, axis) -> Vec<dx>`。
- 基准：单层对齐 → 画布（`view` 换算后的可见区）；多层 → 多选外接框。
- 外框取值：`Raster` 用 `bounds()`（有 `transform` 时用 AABB），`Mark` 用 `mark.rect`。
- 落盘一条 `SetLayersOffset`。

## 5. 迁移映射

| 旧 | 新 | 说明 |
|----|----|------|
| `doc.base` | `layers[0].content = Raster { image, offset: -view.xy }` | 初始化时把 `view` 平移到 offset，几何等价 |
| `doc.view` | 保留 | 裁剪仍只改视窗 |
| `doc.base_deleted` | 删除 | `layers[0].image` 全透明即等价 |
| `doc.base_hidden` | 删除 | `layers[0].visible` |
| `doc.base_converted` | 删除 | `layers[0].locked == false` |
| `session.base_locked` | 删除 | `layers[0].locked`，并入历史 |
| `doc.marks: Vec<Mark>` | `layers` 末尾追加 `Mark` 条目 | 顺序不变 → 视觉不变 |
| `selected_mark: i32` | `selected_mark_id: LayerId` | QML 侧保留"标记列表"视图，交互代码改动最小 |
| `layers_json[].base:true` | `background:true`（同时**保留** `base` 别名一个版本） | 老探针脚本不至于全废 |
| `AdjustTarget::Base` | 保留枚举，内部映射到 background 层 | 调色/擦除面板零改动 |
| `EditOp::DeleteBase` | `ClearBackground` | 语义不变（清空像素，可撤销） |
| `EditOp::BaseToLayer` | 删除 | 不再需要（解锁即普通层） |
| `EditOp::AddMark` / `DeleteMark` | 复用 `AddLayer` / `RemoveLayer` | `UpdateMark` 保留（标记自己的属性） |

## 6. 分阶段实施

每阶段**独立可编译、可发布**，出问题能停在上一阶段。

### P0 · core 模型收敛（行为零变化）
- 改组 `Layer` / `LayerContent`；`Document` 初始化时把 base 塞进 `layers[0]`。
- `composite_pixel` / `flatten` 改单循环；`marks` 迁到 `layers`。
- 更新全部 core 单测（当前 212 条）。
- **验收**：改造前后对同一批脚本场景输出 `flatten()` 的 SHA-256 **完全一致**（新增 `--script=hash:` op 生成基准）。

### P1 · bridge 命令层
- 图层命令：`new_empty_layer` / `duplicate_layer` / `merge_down` / `merge_visible` / `flatten_stack` / `rasterize_mark` / `align_layers` / `distribute_layers`。
- 属性批量化 + 锁定入历史 + `SetLayersOffset`。
- `layers_json` 增加 `id` / `background` / `kind`，保留 `base` 别名。
- **验收**：新增 `scripts/probe_layer_ops.py`（约 20 项）；现有探针全绿。

### P2 · 面板重做
- `LayerPanel.qml` 重写：行高 44、缩略图、名称 + `W×H @x,y`、批量操作条、多选、统一的右键菜单。
- 标记区与图层区合并为同一个列表（标记行用图标区分），`MarkBar` 只保留"绘制工具"。
- 新增 `ImageProvider` 缩略图；`build.rs` 注册。
- **验收**：`scripts/probe_layer_panel.py`（缩略图非空、多选计数、批量隐藏、对齐结果）。

### P3 · 回归与收尾
- 全量探针 + 手动清单补 §A25（图层管理）。
- 更新 `docs/大版本重构-手动测试清单.md`、`MEMORY.md`。
- 打正式包。

## 7. 用户可感知的行为变化

1. 图层面板里"背景"不再是特殊行（仍默认锁定，图标与其它行一致）。
2. 点背景的锁 = 只是解锁，不会再"偷偷把背景变成图层、清空选中"。
3. 标记进入同一个图层列表，**可以拖动排序、可以压在图层下面**，也获得不透明度/锁定。
4. 锁定操作可以 Ctrl+Z 撤销。
5. 新增命令：新建空层、复制图层、向下合并、合并可见、拼合、对齐/分布、批量显示隐藏。
6. 多选（Ctrl/Shift 点击）可批量操作，但**拖动仍只动主选中层**。

## 8. 风险与回归

| 风险 | 影响 | 缓解 |
|------|------|------|
| 标记进入 z 序 | 渲染结果与旧版本不同（若用户拖过标记） | P0 迁移把标记追加到末尾 = 视觉等价；哈希基准对照 |
| GPU 快路径 | 拖动时上方图层被盖住 | 限制为仅最顶层启用；`probe_gpu_overlay` |
| 吸附候选来源改 layers | 咬合/对齐线可能变化 | `probe_holes_snap` / `probe_gap_fit` / `probe_ratio_snap` |
| `marks.rs` 553 行按 id 改写 | 标记交互回归 | 保留 `marks_json` 视图 + 现有 `mark-*` 脚本 op 内部换算 |
| 探针依赖 `layers_json` 字段 | 大量脚本 FAIL | 保留 `base` / `i` 兼容字段至少一个版本 |
| 背景 `view` 与 offset 换算 | 裁剪后位置错 | P0 哈希基准必须覆盖"裁剪 → 合成"场景 |

## 9. 待确认
