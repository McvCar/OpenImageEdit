## 2. 目标架构：独立变换状态层

### 2.1 数据模型（新增 `crates/core/src/layer_transform.rs`）

**D9：params 是唯一事实源，矩阵只是派生值。** 选 params 而非裸矩阵，是为了让数值面板的 X/Y/W/H/角度稳定可回写，也避免「旋转 + 非等比缩放」后矩阵分解的二义性；同时让历史/序列化只存几个浮点数。

```rust
/// 变换参数 = 唯一事实源；矩阵由它推导。
pub struct LayerTransform {
    pub source: Arc<RgbaImage>,       // 未插值原图，变换期间只读；快照克隆只增引用计数
    pub center: (f64, f64),           // 原图中心在画布坐标系的位置
    pub scale: (f64, f64),            // 相对原图尺寸的倍率（负值/翻转另见 flip）
    pub rotation: f64,                // 度，累计角，不归一
    pub flip: (bool, bool),
    pub skew: (f64, f64),             // P0 恒为 0；P1-A 的 Ctrl 斜切启用
    /// P1-A 的 Ctrl 透视：3x3 单应（去掉 [8]=1 后的 8 个系数）。
    /// P0 恒为 None；现在就预留字段与序列化版本号，避免 P1 再改历史格式。
    pub perspective: Option<[f64; 8]>,
}

impl LayerTransform {
    pub fn matrix(&self) -> Affine2;          // source px → canvas px（像素中心 0.5 约定）
    pub fn inverse(&self) -> Affine2;         // canvas px → source px，采样/命中测试用
    pub fn bounds(&self) -> RectF;            // 4 角变换后的轴对齐外接框，允许负坐标/超出画布
    pub fn quad(&self) -> [(f64, f64); 4];    // 旋转后的真实四角，供手柄/参考线用
    pub fn hit(&self, p: (f64, f64)) -> bool; // inverse → 原图矩形 + alpha 阈值
    pub fn panel_values(&self) -> PanelValues;      // D10：外接框左上 + 外接框 W/H + 角度
    pub fn set_panel_value(&mut self, field: Field, v: f64, pivot: ReferencePoint);
}
```

矩阵约定（与 `crates/core/src/transform.rs:193-205` 现有的中心对齐/像素中心约定保持一致）：

```
M = T(center) · R(rotation) · S(scale) · F(flip) · K(skew) · T(-w/2, -h/2)
```

`Layer` 改为持有 `transform: LayerTransform`（或 `source + transform` 两字段），`offset` / `image.width/height` 不再作为几何真值；`bounds()` 由 `transform.bounds()` 派生。

**P1 透视对类型的影响（现在就要定）**：仿射 `Affine2` 表达不了透视。P0 保留 `Affine2` 实现，但 `matrix()/inverse()` 的返回类型在 P1-A 升级为 `enum Transform { Affine(Affine2), Homography(Mat3) }`（或统一用 3×3）；`sample_affine` 相应改为按行求逆单应。字段与历史版本号在 P0-0 就预留，这样 P1 只是补一条采样分支，不动数据模型、不迁移旧文件。

### 2.2 唯一几何真值带来的直接收益

* 缩放 → 再放大：改的是 `scale`，采样始终从 `source` 出发 → **不再累积模糊**。
* 旋转 → 拉伸 → 再旋转：改的是 `rotation/scale/center`，没有外接矩形二次烘焙 → 框不再膨胀。
* 拖动中文档像素与 `edit_epoch` 完全不动（沿用既有铁律），但预览只有**一条** live 分支 → `clear_live_gestures` / `rotate_origin` / `sync_rotate_origin_after_scale` 整类补丁可删。
* `layers_json` 改报 `quad` + `bounds`（含负坐标），8 点、旋柄、徽标全部由它驱动，框与内容天然同步。
* params 形式让 D10 的外接框数值面板、D14 的修饰键约束都变成「同一份参数上的求解」，不需要矩阵分解。

### 2.3 渲染与历史

* **采样器**：把 `transform.rs` 里已有的预乘 alpha 双线性 / Catmull-Rom 取样（`render_rows` / `render_rows_hq` / `normalize` / `expanded_size`）抽成 `sample_affine(src, inverse, out_rect, hq)`，供 core 与 render 共用；预览 `hq=false`、提交与导出 `hq=true`。**D14 的一致性要求**：core 与 render 必须用同一个函数，质量只允许「拖动临时帧 vs 静止/落定帧」这一级差异，不允许两条实现（详见 §9.1、§11.6）。
* `Document::composite_pixel` / `flatten`：逐层按 `bounds() ∩ canvas` 求输出矩形，逆变换取样、alpha-over 混合。**导出仍是 `canvas` 尺寸**（D2）；画布外像素直接跳过（D3/D12）。
* `render::PreviewComposer::composite_adjusted`：同一套逆变换取样；缓存键从 `(epoch, target)` 扩成 `(epoch, target, transform_rev)`，源位图缩放结果可长期复用（源图不变），每帧只重算矩阵。
* **历史**：新增 `EditOp::SetLayerTransform { index, from: LayerTransform, to: LayerTransform }`，只存参数，不再 `from = self.snapshot()` 整文档快照；`ScaleLayer` / `RotateLayer` / `TranslateLayer` 由适配层转成新 op（Phase 2 先保留旧行为，Phase 3 再删）。`DocumentSnapshot` 因 `Arc<RgbaImage>` 变成浅拷贝。
* **只有「写像素」的操作才触发烘焙（D11）**：`adjust_pixels`（点「确定」时）、`write_patch` / `commit_patch`（画笔 / 擦除 / 修补）、`erase_selection_on`、`selection_layer_on`、粘贴。统一走一处 `Document::ensure_baked(index)` —— 先用 `hq=true` 把当前变换一次性重采样成新 `source`（参数归位为 identity + 新 center），再执行像素操作，两者合并成**一条**撤销记录。
* **只读操作一律不烘焙**（从上一轮列表里剔除，缩小触发面）：`scope_image` / `scope_histogram`（直方图）、`magic_wand_selection` / `quick_select_selection`（生成选区，画布坐标）、`layer_pixel` / `composite_pixel`（拾色）、以及调色面板的 live 预览（`render/src/lib.rs` 的 `adjust_preview` 单测已确认「never touches the doc」）。它们直接对合成结果取样即可，不写文档、不产生重采样。
* 不做「patch 反变换回源图坐标系」的完全非破坏方案（成本高、且旋转后插值不可逆）。代价是烘焙后该图层失去继续无损缩放的能力，需在 UI 提示；`from` 保存旧 `source` + 旧 params，`Ctrl+Z` 可完全恢复。输出影响与等价性契约见 **§2.4**，风险见 §7 R3。
* **文档级操作**：裁剪 / 画布 resize 必须把 `center` 平移 `-(delta)`（既有约定：图层 offset 与 `mark.rect` 都是画布相对坐标）；`TransformDocument`（90°/翻转）改为把变换矩阵左乘进 `LayerTransform`，不再重采样位图。

### 2.4 自动烘焙对最终输出的影响（D11 的等价性契约）

**结论：影响的是「以后还能不能无损改」，不是「当前这张导出图」。** 分场景：

| 场景 | 是否烘焙 | 对最终输出的影响 |
| ---- | -------- | ---------------- |
| 只做移动 / 缩放 / 旋转，然后导出 | **不触发** | `flatten()` 从 `source` 一次 HQ 逆变换取样。现状是每变换一次就写回一次（`flatten` 当前是 `x - offset` 1:1 索引，见 `document/mod.rs:811-849,937-951`），新架构反而**少掉 N 次累积重采样**，画质更好 |
| 变换后写像素（应用调色 / 画笔 / 擦除 / 修补 / 粘贴） | **一次** HQ 重采样 | 与「不烘焙直接合成」应像素等价，差异只来自浮点取整 / clamp（≤1 LSB）；比现状「每次缩放旋转都烘焙一次」损失小得多 |
| 整数平移 / 90° 旋转 / 水平垂直翻转 | 走**无损快路径** | 纯索引重排，不做插值，数学上零损失 |

* **唯一实质性代价**：烘焙后 `source` 被固化。若变换是「缩小」，高频细节不可恢复，之后再把该层放大就回不到原始锐度 —— 但**当前这次导出本来就是这个缩小尺寸**，所以输出不额外亏，亏的是后续编辑自由度。`from` 保存旧 `source` + 旧 params，`Ctrl+Z` 可完全恢复无损态；保存格式本身是扁平图像，重开文件后本来就不带图层/变换状态。
* **不做「patch 存源图坐标系」的理由（补充）**：把画布坐标定义的笔刷 / 调色反变换回源图坐标，会让笔刷变形、选区边缘锯齿、alpha 混合权重错乱，输出反而更差且不可预测；旋转插值本身不可逆。

**四条会让输出真的变差的实现陷阱（必须避免）**：

1. **采样器不一致**：烘焙与 `flatten` 必须是同一个 `sample_affine(hq=true)`，否则拖动预览 / 松手 / 导出三个结果都不同（即 R11 / D14）。
2. **identity 图层被二次插值**：烘焙后该层以 identity 参与合成时必须 1:1 索引拷贝，不能再走一遍采样，否则整幅发糊。现有 `render/src/lib.rs:72-74`「同尺寸直接 clone」就是该快路径的雏形。
3. **透明像素未预乘**：擦除 / 旋转后的半透明边缘不做预乘 / 反预乘会泛黑边。直接复用 `render/src/lib.rs:68-131` 的 `resize_to` / `premultiply` / `unpremultiply`（已按「是否含透明像素」分支处理）。
4. **边界处理**：旋转烘焙成外接矩形 `source` 时别裁掉半透明边缘；烘焙结果不得再次被喂进烘焙（幂等保护）。

**验收闸门**：新增 `--probe-bake`，对同一变换分别走「bake → flatten」与「不 bake → flatten」逐像素比对，最大差 ≤1 LSB；无损快路径要求严格 0 差异；缩小再放大场景单独断言「当前输出无额外损失」。一次性 HQ 不在拖动帧发生，大图的可感知停顿用异步 + 进度提示处理（这是响应性，不是画质）。

### 3.1 ① 独立变换状态层（D5/D9，核心、其余四项的地基）

### 3.2 ② 图层变换不钳画布 + 画布外不渲染（D1/D2/D3/D12）

**去钳制**：`EditorContent.qml:1404-1417` 删除 `maxW/maxH` 与 `Math.max(0, …)`，允许 l/r/t/b 为负或大于预览宽高；`commitLayerScale` 的 `Math.round(scaleX/s)` 直接把负 offset 传给 Rust。`SelectionViz.qml:26-41` 保持不动（D0）。

**渲染策略：画布外像素一律不画，零额外渲染路径**（用户为减性能开销撤销了半透明 ghost 方案）：

* 主预览 BMP 尺寸与 `previewImage` 几何**完全不变**；`composite_live_transform` / `composite_adjusted` 只遍历 `bounds ∩ canvas`，越界部分在求输出矩形时就被裁掉，不产生任何像素、不分配 margin 缓冲。
* **不新增** `Session::pasteboard_render` / `PreviewComposer::composite_pasteboard` / `pasteboard_url` / `pasteboardImage`；`CanvasView.pad` 保持现有 64 显示像素、`contentWidth/Height` 不动。手柄拖出 64px 之外时靠既有指针捕获继续接收事件，不需要把工作区扩到能「看见」画布外内容。
* **画布外仍要显示的是控件，不是像素**：8 点、旋柄、外层虚线框、尺寸徽标按 `quad/bounds` 绘制，允许越出画布（`SelectionViz.qml` 已有的徽标不钳制行为保持），这样图层被拉大后还能继续抓住手柄调整。`layers_json` 照常报负坐标 / 超画布 bounds。
* **两个被明确拒绝的方案及原因**：
  1. 把主预览 BMP 扩成含边距的大图 → 改变 `previewImage.width` 语义，连带 `toDispScale()`、`toImage()`、`selX/Y/W/H`、fit/zoom/dpr 预测公式、标记坐标全部重算；
  2. 独立 `pasteboardImage` 画半透明 ghost（原 D3）→ 每帧多一次全幅合成 / 一张纹理 / 一次 BMP 编码写盘，与「减少性能开销」冲突，本轮撤销。
* **体验提示**：内容在画布外不可见时，用外层虚线框 + 徽标（可显示「部分超出画布」）提示，避免用户误以为图层丢失；不再做任何透明区域绘制。

**验收**：八向手柄把图层拉出画布边缘不被挡住；画布外没有任何像素绘制（用合成区域计数器断言 `out_rect ⊆ canvas`）；`Ctrl+S` 导出分辨率与原图一致，画布外内容不出现在导出里；普通选区仍被钳在画布内；框/手柄在画布外仍可点中。

### 3.3 ③ 智能参考线（D6/D15/D16/D17，参数已定稿）

#### 3.3.1 PS 的架构：三件事互相独立（必须先照抄这个分层）

| 开关 | 作用 | 关掉之后 |
| ---- | ---- | -------- |
| `视图 > 显示 > 智能参考线` | 只控制**提示线显不显示** | 线没了，对象**照样被吸过去** |
| `视图 > 对齐`（Snap） | 控制**是否真的吸附** | 线可能还在，但不吸 |
| `视图 > 对齐到`（Snap To） | 控制**候选目标**：参考线 / 网格 / 图层 / 切片 / 文档边界 / 全部 / 无 | 可只留一类目标 |

本项目落地为**两个独立开关**（`show_guides` / `snap_enabled`，都默认开、写进 `settings.ini`，与 D13 同一套 `persist_config()` 链路）：关显示只隐藏 `SmartGuides.qml`，`solve()` 照样跑；关吸附才跳过 `solve()`。候选类别按优先级固定排序，暂不提供逐类勾选（转 P1）。

#### 3.3.2 求解契约（`crates/core/src/snap.rs`，纯几何、不依赖 Qt）

```rust
pub struct SnapCandidate { axis: Axis, pos: f64, kind: CandidateKind, owner: i32 }
pub struct SnapResult {
    pub dx: f64, pub dy: f64,
    pub guides: Vec<GuideLine>,                // 轴线 + 端点，供 QML 直接画
    pub labels: Vec<DistanceLabel>,            // 距离数值（像素）
}
pub fn solve(moving: &[SnapCandidate], statics: &[SnapCandidate],
             threshold_display_px: f64, disp_scale: f64) -> SnapResult;
```

候选数组在**手势起手时**预生成并排序，每帧二分查找，零堆分配 —— 这是 §11.7 的 ≤0.5ms 预算前提。

#### 3.3.3 参数总表（本轮定稿，D16）

| 项 | 定值 | 说明 |
| -- | ---- | ---- |
| **阈值** | **8 个显示像素** | 对标 PS「approximately 8 pixels / 8 screen (not image) pixels」。换算 `threshold_image = 8 / disp_scale`，其中 `disp_scale = toDispScale() = previewImage.width / bridge.image_width`（`EditorContent.qml:1276-1279`，显示像素/图像像素）。**P0 按 QML 逻辑显示像素计、不额外乘 dpr**，保证跨缩放与跨屏手感一致 |
| **候选优先级** | 画布中心 / 画布边 > 其它图层 `bounds` 边与中心 > 选区包围盒 > 等间距推断线（P1） | 同一轴上命中多个时取偏差最小者 |
| **参与求解的边** | `move`：四条边 + 中心；`scale`（八向）：**只让被拖的那条边/角参与，对侧锚点固定**（D16 确认） | 对侧锚点不动是缩放不跳变的前提 |
| **双轴同时命中** | 各轴独立取最小偏差，**可同时吸附、同时画两条提示线** | 不做「只吸一个轴」的取舍，避免斜向对齐别扭 |
| **旋转后的斜边** | **P0 不吸**，只用轴对齐 `bounds` 的四边与中心 | 斜边求解复杂度与收益不匹配；转 P1（R13） |
| **等间距吸附** | **P1**，P0 只在 `SnapResult` 里预留 `DistanceLabel` 与候选扩展位 | PS 也是 CC2014 才补；需推断候选间距，成本高 |
| **距离数值** | **进 P0**：移动中在提示线旁显示对象间距（像素），实时更新 | 只是文本标签，不引入新渲染路径 |
| **提示线样式** | 细洋红（pink/magenta）**静态线 + 数值**，无动效；命中后保持到松手，离开阈值即消失 | 与既有「虚线框不要动效」偏好一致；冻结相位见 §11.3 |
| **临时禁用吸附** | **Ctrl（按 D17 手势分流，见下表）** | 不照抄 PS 的全局 Ctrl，见 3.3.4 |
| **角度吸附** | Shift 15° 吸角由 D14 单独实现（§9.1），**不并入 `snap.rs`** | 两者只在「同时显示提示」时协调优先级：吸角命中时隐藏位置提示线 |

#### 3.3.4 Ctrl 冲突裁决（D17，按手势类型分流，不按「会话」分流）

上一轮建议里说「纯移动工具下 Ctrl 禁用吸附、变换会话里 Ctrl 归斜切」，落到本项目状态机需要**再精确一层**：拖图层内容（`Transform(move)`）本身就属于同一个 `TransformSession`，所以按会话区分会自相矛盾。正确分界是**手势类型**：

| 手势 | 用户动作 | Ctrl 的语义 | Shift / Alt |
| ---- | -------- | ----------- | ----------- |
| `move` | 拖图层内容 | **临时禁用吸附**（PS 移动工具语义） | Shift / Alt 在按下瞬间仍按 `CanvasSurface.qml:66-89` 让位选区；进入 `move` 手势后不参与变换求解 |
| `scale` | 拖 8 点 / 四边 | **斜切 / 透视**（D14） | Shift 锁比例、Alt 从中心 |
| `rotate` | 拖旋柄 | **斜切 / 透视**（D14） | Shift 15° 吸角 |

`TransformSession::update` 拿到 `mods` 位掩码后，先按 `gesture` 查这张表，再决定是「跳过 `solve()`」还是「写 `skew/perspective`」；QML 只透传，不解释。`Ctrl+U` 之类 PS 快捷版本差异较大（`Ctrl+U` 在很多版本是色相/饱和度），**不照抄**，本项目用设置面板 + 按钮控制两个开关。

#### 3.3.5 求解与渲染落点

* 求解在 Rust（图像坐标是唯一真值），`snap_enabled=false` 或 `move`+Ctrl 时直接返回 `SnapResult::default()`；结果作为 `TransformSession` 的字段叠加在几何求解之上，**不写进文档、不进历史**。
* QML 只画 `SmartGuides.qml`（**新 QML 文件必须登记到 `crates/ui/build.rs` 的 `.qml_files([...])`**），数据源是 `transform_state` 里随每帧一起发的 `guides/labels` 数字，不重发结构 JSON（§11.3）。
* 提示线属于叠加层，不受「画布外不渲染」裁剪影响（D12 裁的是像素内容，不是控件）。

**验收（P0-4）**：8 显示像素阈值在 25% / 100% / 400% 缩放与不同 dpr 下手感一致；画布中心/边、其它图层边/中心、选区包围盒都能吸附；双轴同时命中正确；八向缩放时对侧锚点坐标恒定；`move`+Ctrl 不吸附但 `scale`+Ctrl 仍能斜切；关显示仍吸附、关吸附不吸附；求解 p95 ≤0.5ms 且不产生额外重绘。

**转 P1 的剩余项**：等间距吸附、旋转后斜边吸附、Snap To 逐类开关、文字层视觉边界、参考线/网格/切片作为候选目标。

### 3.4 ④ 统一自由变换会话（D4，保留 Preview 手感）

**状态机**（只保留一个 `TransformSession`，替换三套 begin/update/end）：

| 状态 | 进入条件 | 行为 |
| ---- | -------- | ---- |
| `Idle` | 默认 | 命中测试用 `LayerTransform::hit()`（逆变换 + alpha），比现在的矩形 `topLayerAt` 更准 |

| `Selection` | **选区存在且按在选区内部**（与图层重叠时） | 选区手势优先，`layerPickAt` 返回 `null`；**不清选区**（`CanvasSurface.qml:66-89` 规则保留） |
| `Transform(move\|scale\|rotate)` | 命中图层内容 / 8 点 / 旋柄 | 同一个 session：记录 `from` 参数、手势类型、锚点、pivot、起始指针、**修饰键位掩码**、吸附结果 |

* 新 qinvokable 三件套 `transform_begin/update/end` + `transform_set_params`（数值面板）+ `transform_state`（探针）；旧的 `drag_translate_*` / `scale_layer_*` / `rotate_layer_*` 先留**探针别名**，保证 `scripts/paint_probe.sh`、`verify_paint.py`、`--probe-rotate` 不失效，Phase 3 后再删实现。

* `V` 开关 `moveMode`、`paintTool` / `markTool` 让位规则、`host.selTool` 判定全部保持不变。
* 可删除：`LiveScaleState`、`RotateLive`、`LiveRotate`、`RotateOrigin`、`rotate_token`、`live_cap`、QML 的 `rotateFrames` / `rotateFrameAngle` 按索引记忆逻辑、以及 `clear_live_gestures()` / `sync_rotate_origin_after_scale()`。

**验收**：`rotate-hold:45` 后拖 60px 不再出现 `live-stale`；旋转→拖边缘、旋转→拉伸→再旋转、`Esc` 取消、连续多次旋转角度不复位；选区压在图层上时拖动仍归选区。

### 3.5 ⑤ 变换数值面板（D7/D10/D13）

* 新 `qml/panels/TransformPanel.qml`（登记 `build.rs`）：**首次默认隐藏**，由工具栏/图层面板的**按钮点击**切换显示（不加快捷键，避免占用 P1 的 `Ctrl+Shift+T`）；面板首次展开停靠工作区左上角。
* **记住上次显示状态（D13）**：复用现有持久化链路 —— `AppConfig`（`crates/ui/src/bridge/config.rs:6-35`）新增 `transform_panel_visible: bool`，`load/save` 加一个 key；Bridge 加 qproperty `transform_panel_visible` 与 `#[qinvokable] update_transform_panel_visible(bool)`，setter 照 `ops/settings.rs:98-104` 的模式调 `persist_config()`（`mod.rs:1167-1183`）；QML 的 `visible` 绑定该属性，按钮只调 setter。跨启动保持，与「记住上次选区工具 / 形状」的现有行为一致。
* 字段与语义（**D10**）：
  * **X / Y = 变换后轴对齐外接框左上角**（画布图像坐标，可为负 / 超出画布）；
  * **W / H = 变换后外接框宽高**（不是原图尺寸 × scale；旋转后外接框会因角度变大）；
  * 角度、锁定比例、水平/垂直翻转、插值方式、3×3 参考点；只读时显示选中图层当前参数。
* 内部换算：`center = (X + W/2, Y + H/2)`；写回 W/H 时按**当前 `rotation` 不变**反解 `scale`（外接框宽高是 `w·|cos|·sx + h·|sin|·sy` 一类的组合，需按当前 angle 求解，参考点决定哪个角/中心不动）。这正是 D9 选 params 的价值：不需要从矩阵分解出 scale/angle。锁比例与参考点规则要在 P0-5 用单测固定，避免 90° 附近数值抖动。
* 所有写入走 `transform_set_params` → 同一条 live 预览 → 输入框失焦/回车时合成**一条**历史；不产生每按键一条撤销记录。
* 数值改动与画布拖拽共享 `TransformSession`，不存在两套状态。

## 4. 统一后的数据流

```
指针事件(QML) ──> transform_begin/update/end(mods) ──> Session::transform: Option<TransformSession>
                                                    │ from / current: LayerTransform (params)
                                                    │ snap: SnapResult (P0-③)
                      ┌───────────────────────────────┴───────────────────────┐
                      │ live 预览：composite_live_transform(doc, target, current) │
                      │ 输出矩形 = bounds ∩ canvas（画布外像素不采样、不绘制）   │
                      └───────────────────────────────┬───────────────────────┘
                                       松手 ─> EditOp::SetLayerTransform（一条历史）
                                                    │
                    导出/flatten：逆变换取样 source，输出 canvas 尺寸（D2）
```

`layers_json` 报 `quad/bounds/angle/center`，QML 的 8 点、旋柄、尺寸徽标、`topLayerAt` 全部只读它，不再各自缓存一份几何。框与手柄允许越出画布；像素不越出。

## 9. P1 / P2 路线

### 9.1 P1-A：修饰键语义与插值一致性（D14，用户已明确要求）

**现状 vs PS（代码事实：`EdgeHandles.qml:73,168` → `EditorContent.qml:1404-1425`）**

| 手势 | 当前行为 | PS 目标行为（D14） |
| ---- | -------- | ------------------ |
| 拖角点 | **默认锁比例**，Shift 才自由（语义反了） | **默认自由**，Shift 锁比例 |
| 拖角点 + Alt | 无 | **从中心缩放**（对侧同步反向变化） |
| 拖边中点 | 单轴缩放 | 单轴缩放；Alt 从中心 |
| Ctrl + 拖角点 / 边 / 旋柄（`scale`·`rotate`） | 无 | **斜切 / 透视**（沿用 PS 组合：Ctrl 自由扭曲、Ctrl+Shift 斜切、Ctrl+Alt+Shift 透视；若简化，至少实现斜切与透视两种） |
| **Ctrl + 拖图层内容（`move`）** | 无 | **临时禁用吸附**（PS 移动工具语义，D17）；此手势下 Ctrl **不**触发斜切 |
| 旋转 | 自由角度，无吸角；仅 `RotateLayerOverlay.qml:130-131` 有 ±15° 按钮 | **Shift 吸 15° 整数倍**（`round(θ/15)·15`），松开 Shift 回到连续角度；Alt 可改旋转中心（可选） |
| 拖动中 / 松手 | 拖动 Nearest 或双线性、松手 Lanczos3，两条实现 | **同一采样器 + 明确的质量分层**（下述） |

**实现落点**

1. `EdgeHandles.qml:73,168` 与 `CanvasSurface.qml` 的旋转手势不再把 Shift 解释成 `free` 布尔，改为把 `mouse.modifiers` 完整位掩码 + `gesture` 类型传到 `TransformSession::update`；`resizeLayerFrom` 的 `free` 参数删除。语义**只在 Rust 一处求解**（params 上算新 `scale/center/skew/perspective`），QML 不参与。
2. `TransformSession` 记录起手 `from` params 与 pivot，**先按 `gesture` 查 §3.3.4 分流表**，再按 mods 求解：Shift → 锁比例 / 15° 吸角；Alt → 锚点从「对侧」改为「中心」；`scale`/`rotate` 下的 Ctrl 组合 → 写 `skew` 或 `perspective`（R8 的类型预留在此启用）；`move` 下的 Ctrl → 直接跳过 `snap::solve()`。所有结果都仍是 params，历史仍是一条 `SetLayerTransform`。
3. **插值一致性（R11）**分两件事：
   * *实现一致*：core 的 `flatten/composite_pixel` 与 render 的 `composite_live_transform/composite_adjusted` 共用 `sample_affine`，禁止再出现「预览 Nearest / 提交 Lanczos3」两套代码；
   * *观感一致*：Tier 1 GPU 快路径拖动是双线性（GPU 采样），落定是 Catmull-Rom/Lanczos3，两者必然有细微锐度差 → 用「静止 >100ms 异步补一帧 HQ + 落定时 1 帧（~80ms）交叉淡入」消除突变，或 1.5× 超采样 + mipmap（§11.6）。**不允许**为了让两者一致而把落定画质降到拖动水平。
   * *验收*：`--probe-perf` 增加像素差分字段：同一变换「拖动落定后的像素」与「一次性直接提交该 params 的像素」差值低于阈值；Shift 吸角后角度必为 15 的倍数；Alt 从中心时 `center` 在手势中恒定；`move`+Ctrl 不吸附、`scale`+Ctrl 仍能斜切。

**其余 P1（按 D8 缓做）**：`Ctrl+Shift+T` 再次变换、复制并变换、`LayerPanel` 无对齐/分布、无历史面板；**智能参考线转 P1 的三项**（等间距吸附、旋转后斜边吸附、Snap To 逐类开关，见 §3.3.5）；「历史整文档快照」「旋转后 8 点贴轴对齐外接矩形」会在 P0-1 / P0-2 顺带消掉大半。

## 11. 性能与流畅性方案（P0 各阶段的强制验收项）

### 11.1 现状：一次拖动帧实际付了什么

| 环节 | 现有实现 | 代价 |
| ---- | -------- | ---- |
| 事件节流 | `liveTimer` 33ms / `scaleTimer` 40ms（`CanvasSurface.qml:1055, 1300`） | 固定定时器与 vsync 不对齐，会抖；积压事件不合并 |
| 状态同步 | `refresh_preview_inner` → `session.refresh()` 每帧重发 `layers_json()` + `marks_json()`（`session.rs:815-816`） | 每帧两次 JSON 序列化 + QML parse |
| 合成 | `composite_adjusted` / `composite_live_*` 每帧把 base 与**所有其它图层**按全 `target` 尺寸重新 blend（`render/src/lib.rs:403-418, 584-599`） | O(预览像素 × 层数)，与活动层无关也要付 |
| 缓冲 | `base_buffer` 每帧 `(*img).clone()`（`:279-280`） | 每帧一整幅 RGBA 拷贝 + 分配 |
| 旋转 | live 分支每帧 `rotate_into` 整层双线性（`:621-622`，已缓存 `rotate_small`） | 仍是整层重采样 |
| 编码/落盘 | `encode(…, Bmp)` + `std::fs::write` 到临时文件（`session.rs:548-556`） | BMP 未压缩已是最优解，但仍有整幅 `Vec` 分配 + 一次磁盘写 |
| 解码/上传 | 双 `Image` 异步解码、`cache: false`（`CanvasView.qml:315-343`） | Qt 重新解码 + 全幅纹理上传 |
| 叠加层 | 8 点 / 虚线框 / 徽标 / 选区蚂蚁线 `Canvas` 16ms 定时器（`CanvasSurface.qml:764-772, 1080-1085`） | 拖动时仍在逐帧 `requestPaint` |

**结论**：即使 §2 的独立变换状态层消掉了「反复烘焙」，只要还走「每帧整幅 CPU 合成 → 编码 → 写盘 → 解码 → 上传」，4K 图 / 多层 / debug 构建下 60fps 仍不稳。所以性能不能当收尾优化，必须和数据模型一起设计。D12 撤销 ghost 后，还少了一条本来会新增的全幅渲染链。

### 11.2 三条原则

1. **变换期间只改矩阵，不改像素、不换纹理**（retained texture + matrix）。
2. **每帧最多一次跨语言状态更新，且只传数字**，不重发结构 JSON。
3. **质量分层**：拖动求快、静止补清晰、落定一次 HQ；降级只作用于临时帧，**不牺牲最终清晰度**（D14/R11）。

### 11.3 Tier 0 — CPU 路径减负（低风险，随 P0-1 一起做）

* **静态合成缓存**：手势起手把「活动图层以下」和「以上」各合成一次；每帧只复用缓冲 + 在活动层 `bounds ∩ viewport` 区域 blend，不再遍历全部图层。
* **持久 scratch 缓冲**：`PreviewComposer` 持有输出缓冲复用，去掉每帧 `clone()` / `RgbaImage::new` 分配。
* **仿射取样增量步进**：每行只算一次逆变换起点，x 方向加常量 `(a, c)`；`sin/cos` 只在参数变化时算；内部快路径 + 预乘 alpha + 按行并行（复用 `transform.rs` 的 `RotCtx` / `render_rows`）。
* **只算可见区**：`bounds ∩ canvas ∩ 当前视口`；**画布外像素一律跳过**（D12），全幅逆取样只留给导出/落定。
* **状态通道轻量化**：拖动帧只发 `transform_state`（center / scale / angle / quad / guides 几个数字），`layers_json` / `marks_json` 只在结构变化时重发；手柄与徽标改由同一份参数属性绑定驱动，不跑 JS 重算。
* **事件合帧**：把固定 `Timer` 换成与 vsync 对齐的 `FrameAnimation`（Qt 6.4+），或在帧回调里只取「最新指针状态」丢弃积压事件；`pumpPreview` 换台逻辑保留。
* **叠加层降载**：拖动期间冻结选区蚂蚁线相位；图层虚线框保持静态（已有结论）；`DashedRect` 不逐帧 `requestPaint`。
* **历史与内存**：`Arc<RgbaImage>` 让 `DocumentSnapshot` 变浅拷贝，`SetLayerTransform` 只存参数，撤销/重做零像素复制。

### 11.4 Tier 1 — GPU 快路径（P0-2 的核心，把流畅度拉到 WebGL 手感）

P0 的「独立变换状态层」正好让这条路径成立：源位图在手势期间恒定，变换只是一个矩阵。

```
起手（一次）：
  source ──按预览尺度(1~1.5× 超采样)──> activeLayer 纹理（source 全程不变）
  base + 活动层以下的层 ──────────────> staticBelow 纹理
  活动层以上的层 + marks ─────────────> staticAbove 纹理

每帧（零 CPU 重采样 / 零 BMP / 零写盘 / 零解码 / 零全幅上传）：
  只写 QML 属性：activeLayer.transform = Matrix4x4(LayerTransform::matrix())
                 + opacity / 手柄 quad / 参考线
  Qt Quick 在 GPU 上完成采样与三层混合
```

* 三层按栈顺序叠放，`staticBelow` / `staticAbove` 只在 epoch / 栈顺序 / 可见性变化时重建。
* 8 点、旋柄、尺寸徽标、参考线都由同一 `LayerTransform` 参数推导，纯属性绑定。
* **画布外不渲染（D12）**：`activeLayer` 纹理直接用 QML `clip: true` / GPU scissor 裁到画布矩形即可，不需要第二份半透明 draw、不需要 pasteboard 纹理、不需要 0.45 全幅副本 —— 比原 ghost 方案少一次全幅合成与一次 draw call。控件（框/手柄/徽标）在裁剪之外的 QML 层照常绘制。
* **落定**：一次 HQ CPU 逆变换取样 → 重建静态纹理。为避免「拖动偏软 → 落定变锐」的突变（D14/R11），二选一：① 拖动贴图 1.5× 超采样 + `mipmap`；② 切换时 1 帧 (~80ms) 交叉淡入。
* **自动回退 Tier 0**：调色面板开启、快速蒙版 Q、文本内联编辑、活动层挂了 live adjust、marks 依赖 —— 这些状态在拖动中不常见，命中即走 CPU 路径，保证正确性优先。
* 这正是上一轮 WebGL 对比的答案：不是 GPU 更聪明，而是「纹理 retained + 只更新矩阵」；本项目之前每帧都把结果压成一张**新** BMP，才被迫全链路重来一遍。

### 11.5 Tier 2 — 去掉传输环节（可选，收益递减）

用 `QQuickImageProvider` 或自定义 `QQuickItem + QSGSimpleTextureNode` 把内存 `RgbaImage` 直接交给场景图，省掉 BMP 编码 + 临时文件 + Qt 解码（cxx-qt 若不便暴露 `QImage`，加一层薄 C++ 桥接）；保留现有 URL 双缓冲作回退。Tier 1 期间根本不产生新帧，所以这一层不影响主收益，可放到 P0 收尾后单独做。

### 11.6 质量分层与自适应降级

| 阶段 | 分辨率 | 插值 | 触发 |
| ---- | ------ | ---- | ---- |
| 拖动中 | GPU 快路径（1.5× 超采样）或 CPU + `live_cap` | 双线性 | 指针移动帧 |
| 静止 >100ms | 全分辨率 | Catmull-Rom | 空闲异步补帧，不阻塞输入 |
| 松手 / 导出 | 原分辨率 | Catmull-Rom / Lanczos3 | 各一次 |

core 与 render 共用 `sample_affine`，此处只有「质量档位」差异，没有「实现」差异（R11）。降级阶梯（连续 N 帧 p95 超预算时依次触发）：降 `live_cap` → 关异步 HQ 补帧 → 减参考线候选数 → 降超采样倍率；**吸附精度与最终清晰度不降级**。现有 `capped()`（`geom.rs:86-96`）、`live_cap`、`render-skip`（`session.rs:482-499`）直接复用为降级基础设施。

### 11.7 帧预算与验收

| 环节 | 预算（release / debug） |
| ---- | ---------------------- |
| 输入合帧 + 变换/吸附求解（含修饰键约束） | ≤ 0.5 / 1 ms（候选数组起手预排序，每帧二分，不分配） |
| 合成 | Tier 1 ≤ 2 ms（仅矩阵）；CPU 回退 ≤ 8 / 16 ms |
| 编码 / 落盘 / 解码 / 上传 | Tier 1 = 0；CPU 回退 ≤ 4 ms |
| QML 叠加层 | ≤ 2 ms |
| **整帧** | **≤ 16.7 ms（60fps）/ ≤ 33 ms（debug 30fps）** |

* 扩展 `render-profile`（`session.rs:557-564`）增加 `solve` / `ui` / `frame` 字段；新增 `--probe-perf` 输出 p50 / p95 / max、掉帧数与落定像素差分（R11）；`scripts/` 加标准手势序列（连续旋转 3 次 → 拖出画布 → 八向缩放 → 修饰键组合 → 参考线开关），跑在 4000×3000 / 3 层样本上。
* **每阶段性能闸门**：P0-1 CPU 路径 p95 不劣于现状，且 `--probe-bake`（§2.4）「bake → flatten」与「不 bake → flatten」像素差 ≤1 LSB、无损快路径严格 0 差异；P0-2 Tier 1 上线后拖动帧 CPU 全幅合成次数 = 0（计数器断言）；**P0-3 画布外零像素采样、零新增 draw call、零额外纹理，且 `CanvasView.pad` 不变**；**P0-4 吸附求解 p95 ≤0.5ms、不产生额外重绘**（候选起手预排序 + 每帧二分、零堆分配；8 显示像素阈值经 `8 / toDispScale()` 换算；`move`+Ctrl 或 `snap_enabled=false` 时求解次数应为 0；`show_guides=false` 只跳过绘制）；P0-5 数值输入不产生逐键历史或全幅重绘；P1-A 修饰键求解不引入分配、落定像素差达标。
* 明确一条底线：**流畅度不能靠降低最终画质换**。落定后的锐度必须达标（这本来就是 P0 ① 的目标），所有降质只作用于手势中的临时帧。

### 11.8 与 P0 五项的对应关系

| P0 项 | 性能收益 |
| ----- | -------- |
| ① 独立变换状态层（params） | 源位图恒定 → 纹理只生成一次；参数级历史 → 零像素复制；无重复烘焙 |
| ② 去钳制 + 画布外不渲染 | 输出矩形恒 `bounds ∩ canvas`，画布外零采样；无 ghost 纹理 / 无扩边 BMP / 无额外合成与写盘 |
| ③ 智能参考线（8 显示像素 / 双轴独立 / 不吸斜边） | 起手预计算候选 + 每帧二分，纯浮点运算；提示线只画 2~4 条静态洋红线 + 距离文本；两个开关独立，关显示仍吸附、关吸附连求解都跳过 |
| ④ 统一变换会话 | 只有一条 live 分支、一处事件合帧、一次状态发布；修饰键求解也在这一处 |
| ⑤ 变换数值面板 | 复用同一个 transform 属性，不引入新的渲染路径；隐藏时零开销 |

## 12. 一句话总结

先把「变换」从位图里拆出来变成以 **params 为唯一真值**的独立状态层，再用一个会话统一移动 / 八向缩放 / 旋转（修饰键按 PS 语义在这一处求解），画布外不渲染任何像素但框与手柄仍可越界、导出仍是原画布尺寸，像素类操作接受一次性自动烘焙，最后叠加按 PS 定参的智能参考线（8 显示像素阈值、双轴独立、Ctrl 按手势分流、等间距转 P1）与「按钮唤起 + 记住状态」的数值面板 —— 这套结构同时解决「越缩放越糊」「拖不出画布」「没有吸附」、预览与提交插值不一致，以及近几轮所有「框与内容错位 / 角度复位 / 外接框膨胀」的 bug；配套的 Tier 1 GPU 快路径让手势期间只更新矩阵、零全幅重绘，且因撤销了 ghost 方案又少了一整条渲染链，是保证这些新操作依然跟手的关键。
