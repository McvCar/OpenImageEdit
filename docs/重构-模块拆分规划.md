## 0. 结论先行

代码总量约 **19,600 行**，但其中 **79% 集中在 3 个文件**里：

| 文件 | 行数 | 体积 | 问题 |
| --- | ---: | ---: | --- |
| `crates/ui/qml/main.qml` | 7,585 | 314 KB | 一个文件装了外壳窗口 + 10 个控件 + 16 个面板/覆盖层 + 全部交互逻辑 |
| `crates/ui/src/bridge.rs` | 4,955 | 193 KB | 一个 `impl` 块 3,364 行，112 个方法平铺 |
| `crates/core/src/lib.rs` | 2,958 | 109 KB | 几何/图层/标记/栅格化/历史/操作/测试全在一个文件 |

**要做的不是"把大文件切小"，而是把这三处按"功能"纵切成目录树。** 关键判断有两条：

1. **先做无风险的，最后做画布。** 有 10 个 QML 控件是**零外部依赖**的（684 行，直接搬走即可），有 4 个面板**只依赖 `bridge`**（925 行，加一行 `required property var bridge` 就完事）。而画布 `view`（1,196 行）牵动 141 处 `root.`、80 处 `bridge.`、43 处 `view.`，必须放到最后。
2. **Rust 侧的拆分和 QML 侧完全解耦**，可以并行推进；`crates/core` 的拆分有 `cargo test`（53 个测试）做硬门槛，是全程最安全的一块。

    ├── ZoomMenu (2339-2438)  OverflowMenu (2459-2496)

    ├── StatusBar (3766-4069) LayerPanel (4079-4682) AdjustPanel (4687-5104)
    ├── PickerPanel (5122-5377)  ResizeOverlay (5386-5674)

    ├── ConfirmOverlay (6504-6638) PsdHintOverlay (6643-6750) SettingsOverlay (6755-7147)
    └── 20 个探针 Timer (7316-7542)

**病灶 B：`bridge.rs` 的 `impl qobject::Bridge` 是一个 3,364 行的方法墙。**

112 个方法按"写代码的时间顺序"排列，不是按功能分组。同一个功能的代码被拆到文件两处：例如图层的 `translate_selected`（2933 行）和 `drag_translate_update`（3866 行）隔了 900 行；预览渲染 `refresh_preview_inner` 落在文件**最末尾**（4707 行），而想找它得先翻过 3,000 行无关方法。

**病灶 C：`core/lib.rs` 里 1,101 行测试挤在生产代码下面。**

打开 `lib.rs` 要先滚过 1,858 行才能看到测试；加新测试时没有任何"该放哪"的信号。

### 1.3 现在的实际代价

- 改一个面板的样式，需要在 314 KB 的文件里定位，且 `main.qml` 缩进在历史上已被多次改乱（`MEMORY.md` 明确记录"缩进混乱不可信，插入前数括号确认容器"）。
- 多个功能开发时对同一个文件产生结构性修改 → `git merge` 冲突面大。
- 评审一个功能改动，`git diff` 会带上大量上下文噪声。
- 新人（或另一个 agent）想上手，唯一入口是 7,585 行的单文件，没有"这个功能在哪"的路径。

## 2. 目标结构

### 2.1 总原则：按功能纵切，不按层次横切

**错误做法**：`models/` `views/` `controllers/` —— 这样每个功能仍然摊在三处。
**正确做法**：`layers/` `marks/` `canvas/` `color/` —— 一个功能的 Rust 方法 + QML 面板 + 测试都在同一目录附近。

## 3. 拆分规则（QML 部分，这是全项目最容易出错的地方）

### 3.1 三种跨文件引用，三种解法

`main.qml` 现在能跑，是因为**所有东西共享同一个组件作用域**。搬到新文件后，作用域被切断，只有三类引用需要处理：

| 引用类型 | 现状 | 解法 | 是否要改函数体 |
| --- | --- | --- | --- |
| `bridge.xxx`（367 处） | 指向同组件内的 `id: bridge` | 新文件加 `required property var bridge`，实例处写 `bridge: root.b` | **不用改** |
| `root.xxx`（592 处） | 指向 EditorContent 自身 | 新文件加 `required property var host`，函数体内 `root.` → `host.`（脚本批量替换） | 改，机械替换 |
| `view.` / `previewImage.` / `selBadge.` 等其它 id | 组件内平级 id | 加对应 `required property`（如 `required property var view`） | 改，机械替换 |
| **裸函数调用** `applyCrop()` | 解析到 EditorContent 自己的函数 | 先改成 `root.applyCrop()`，再替换为 `host.applyCrop()` | **必须先改，否则静默失效** |

最后一行是最危险的：QML 对未定义标识符只在运行时报一条 warning，界面看着正常，功能已经不通了。实测每个面板的裸调用都很少（`titleBar` 7 个、`layerPanel` 4 个、`adjustPanel` 6 个、`statusBar` 6 个、`resizeOverlay` 6 个），逐个改掉即可，不会漏。

### 3.2 机械化提取流程（每个文件都照这个走）

1. **按括号深度定位**，不按缩进。用 `tmp/qml_depth.py`（本次分析已写好）算出目标块的精确首尾行 —— 项目里缩进已不可信，靠缩进切片必然切坏。
2. 复制该行段到新文件，改根对象：`Rectangle {` → `Rectangle {` 前加 `required property var …`。
3. **删掉块内的 `id:` 行**。id 放到实例处，这样外部对 `settingsOverlay` 之类的引用原样保留。
4. `anchors.fill: root` → `anchors.fill: parent`（新文件里没有 `root`）。
5. 批量替换 `root.` → `host.`；补齐 `bridge:` / `view:` 等入参。
6. 原位置替换成一行实例：
   ```qml
   SettingsOverlay {
       id: settingsOverlay
       anchors.fill: parent
       bridge: root.b
   }
   ```
7. `build.rs` 注册（见 3.3），`cargo build` + 探针验证，**单独提交一次**。

### 3.3 QML 文件怎么注册进去

`build.rs` 现在是：

```rust
CxxQtBuilder::new_qml_module(QmlModule::new("com.imageedit").qml_file("qml/main.qml"))
```

改成把每个组件都列进去即可（已确认 `QmlModule::qml_files` 与 `qrc_resources` 在 cxx-qt-build 0.10 中可用）：

```rust
let mut module = QmlModule::new("com.imageedit").qml_file("qml/main.qml");
module = module.qml_files([
    "qml/widgets/ToolButton.qml",
    "qml/panels/LayerPanel.qml",
    // …
]);
CxxQtBuilder::new_qml_module(module)
    .qrc_resources(["qml/js/layers.js", "qml/js/marks.js"])  // .js 不是组件，走 qrc
    // …
```

要点：

- **文件首字母必须大写**才会被写进 `qmldir` 成为可实例化类型（`main.qml` 保持小写，它是入口，不是组件）。
- qmldir 里的条目形如 `LayerPanel 254.0 qml/panels/LayerPanel.qml`，所以**子目录可以用**，实例化时靠 `import com.imageedit` 就能直接写 `LayerPanel { }`。
- 每个新组件文件都要自带 `import QtQuick` 和 `import com.imageedit`（同一模块内互相引用也要写明）。
- `build.rs` 已有 `rerun-if-changed=qml`，新增文件不用再补，但**加完文件必须重新 `cargo build`**，否则 qrc 里还是旧的。

### 阶段 4 —— 纯函数搬进 `js/`

`EditorContent` 里约 990 行、104 个 function，其中**一半是纯函数**，可以整段搬进 `qml/js/*.js`，用 `import "js/layers.js" as Layers` 调用：

| 目标 | 可搬走的函数 |
| --- | --- |
| `js/geometry.js` | `toImageScale` `toDispScale` `snapDisplay` `canvasCursor` `boxCursor` `boxSet` `resizeBoxFrom` `moveSelFrom` `resizeLayerFrom` `linkedHeight` `linkedWidth` |
| `js/layers.js` | `parseLayers` `findSelLayer` `findLayerBox` `isLocked` `findBase` `nonBaseRowCount` `topLayerAt` |
| `js/marks.js` | `parseMarks` `findMark` `selectedMarkBox` `qmlFontFamily` `markFontName` `stepMarkFontSize` |
| `js/adjust.js` | `parseAdjust` `parseHistogram` |
| `js/picker.js` | `parsePicker` `parsePickerHistory` |

注意：纯函数搬到 `.js` 后**失去组件作用域**，只能访问通过参数传进去的东西。上面这些函数已经满足这个条件（这是筛选它们的依据）。`.js` 文件必须通过 `qrc_resources` 进资源，QML 里用相对路径 `import "js/layers.js" as Layers`。

### 阶段 6 —— `bridge.rs` 拆分（可与 1-5 并行）

**为什么能拆**：`impl qobject::Bridge` 本质是 `BridgeRust` 的**固有无方法实现**（`qobject::Bridge` 只是 `type Bridge = super::BridgeRust;` 的别名，cxx-qt 生成的 C++ 通过 `imageedit$cxxbridge1$...$Bridge$start` 调用同名固有方法）。Rust 允许同一个类型的固有 impl 分散在**同一 crate 的任意模块**里，所以可以按功能切成多个 `impl` 块。

**唯一约束**：`#[cxx_qt::bridge] mod qobject` 里的 qproperty / qinvokable **声明**必须留在同一个模块内（现在在 42-528 行，487 行）。这部分不拆，作为 `bridge/mod.rs` 的固定骨架。

**子模块必须放在 `bridge/` 目录内**（即 `bridge::ops::layers` 这样的后代模块），因为 `BridgeRust` 的字段是私有的 —— 定义模块的后代模块才能访问，这样**一行 `pub(crate)` 都不用加**。

## 5. 技术约束与已知陷阱

| # | 约束 | 后果 | 对策 |
| --- | --- | --- | --- |
| 1 | `main.qml` **缩进不可信** | 按缩进切片会切断括号 | 一律用 `scripts/qml_extract.py` 按括号深度切片并断言平衡 |
| 2 | PowerShell `Get/Set-Content` 改源码按 GBK 写坏中文 | 中文注释/字符串变乱码 | 只用 `edit` / `write` 工具改源码（`MEMORY.md` 已有记录） |
| 3 | qmlcachegen 产物是字节码 | 改完 QML 若没重新 build，跑的还是旧界面 | 每次改 QML 必须 `cargo build`；验证靠行为探针，不靠字符串搜索 |
| 4 | QML 未定义标识符只报运行时 warning | 功能静默失效，界面看着正常 | 每阶段跑对应 `--probe-*` 并检查日志里的 `ReferenceError` / `TypeError` |
| 5 | 小写 QML 文件不进 qmldir | 搬完实例化失败 | 组件文件名一律 PascalCase；`main.qml` 保持小写 |
| 6 | cxx-qt 声明块必须唯一 | 把声明也拆开 → 直接不编译 | 声明块固定在 `bridge/mod.rs`，只拆 impl |
| 7 | `BridgeRust` 字段私有 | 子模块访问不到 → 编译失败 | 子模块放在 `bridge/` 目录内（后代模块可访问） |
| 8 | 多窗口：每个 `EditorContent` 有**自己的** Bridge 实例 | 误做成 QML 单例 → 两个窗口共享状态 | **不要**给 Bridge 做 singleton；跨窗口只共享 Rust 侧的进程级剪贴板 |

| 10 | 构建必须 `. scripts/env.ps1` | cxx 构建挂 clang | 沿用现有构建流程，一次 build 1-3 分钟属正常 |

## 7. 明确不做的事

- **不引入 QML 单例来装 Bridge。** Bridge 是每窗口一份（多文档窗口设计），做单例会破坏现有跨窗口语义。
- **不顺手改行为。** 每个阶段只做"搬 + 接线"，不加功能、不优化、不改命名。混着做会让回归无法定位。
- **不在阶段 1-4 动画布。** `view` 单独一个阶段，且内部再拆 6 小步。
- **不为了"分层"拆 `decode` / `render` / `thumbnail`。** 它们 400-800 行，已经是合适粒度；拆了只会增加跳转成本。
- **不一次性重写 `main.qml`。** 逐步搬空、每步可运行，才是能回滚的路径。
