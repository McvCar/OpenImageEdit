## 0. 一页结论

**能打开，画得"接近"但还不到 PS；而且在编辑态下每帧都按 617 层重算，做不到「保真 + 流畅」同时成立。**
（P0 的合成语义补齐已经落地，MAE 10.67 → 9.24，详见 §4.1。）

三组实测数字（debug 构建，本机 i7-8700）：

| --- | --- | --- |
| 首帧（同步装配 617 层 + 样式烘焙 + 首帧合成） | **3.25 s** | `shown_ms` |
| 分层编辑态内存 | **434 MB** | 617 层按 bbox 存位图，面积合计 41.9 Mpx |

**差距不是「某个混合模式没实现」，而是三层**：

1. **合成语义缺两块地基**（P0 已补）：剪贴蒙版（**210 个可见层**）和图层蒙版（**95 个可见层**）原先在文档模型里根本不存在。补上后这两项合计贡献 **−1.7 MAE**（§4.1），但剩下的误差主要不在这里 —— 见下一条。
2. **特性只能烘焙、不能live**：73 个调整层被逐层烘进下方像素，805 个图层样式被烘进图层位图（其中 775 个在可见层上）—— 几何基本对，但模糊半径、每效果的混合模式/等高线/杂色、调整的作用顺序都是近似。**P0 之后，这是剩余误差的绝对主项**：把样式全关掉 MAE 从 9.24 涨到 13.98（§4.1）。
3. **渲染架构是「整幅重算 + 整幅落盘」**：任何一次编辑都重合成整幅（124 ms），再把整幅编码成 BMP 写进临时文件让 QML 解码（`write` 约 130 ms/帧，5.1 MB/帧）。这条路上加任何特性都救不了交互延迟。

**保真编辑的解法（本方案主张）**：

- **不去重建没被编辑过的像素** —— PS 合并图本身就是逐像素真值，让它当「保真底图」；
- 画布切 **64 px 瓦片**，编辑只重合成**脏瓦片**：实测单块成本 **p50 0.22 ms / p95 1.16 ms**（对比全幅 124 ms，约 100–500×）；
- 脏瓦片内必须**语义正确**（P0 补剪贴/蒙版/组蒙版 + 单次量化），把块内 MAE 从 10.67 压到 ≤ 2 —— 否则编辑处会和周围保真像素出现**接缝**，这比整幅都偏一点更难接受。

分四步：**P0 语义补齐 → P1 瓦片增量 → P2 前缀缓存/遮挡裁剪 → P3 预览链路去落盘 → P4 通用特性**（§4）。

## 3. 编辑态保真架构：保真底图 + 瓦片账本 + 脏块重合成

### 3.1 三条不变式

1. **保真不变式**：任何没有被本次编辑触及的像素，必须逐字节等于 PSD 自带合并图。
2. **最小不变式**：一次编辑的计算量 ∝ 脏区域面积 × 该区域内的图层数，**与文档总层数无关**。
3. **可解释不变式**：任何一块像素从"保真"变成"重建"都要能说出来（哪次编辑、涉及哪些特性、重建后与 PS 差多少）。

### 3.2 数据模型

新增 `crates/core/src/fidelity.rs`（core 不依赖 Qt/image 之外的东西；`RgbaImage` 已在用）：

```rust
pub const TILE: u32 = 64;              // 实测成本与块数的最佳折中（见 §3.5）

pub struct TileGrid { cols: u32, rows: u32 }

pub enum TileState {
    /// 仍是 PSD 合并图的原始像素（逐字节保真）
    Pristine,
    /// 被本编辑器重合成过；epoch = 最后一次重合成的编辑代数
    Rebuilt { epoch: u64 },
}

pub struct FidelityView {
    grid: TileGrid,
    /// PSD 自带的合并图（Document::from_image，1 层）。只读共享。
    base: Arc<RgbaImage>,
    /// 工作合成：初值 = base；被编辑过的瓦片换成自己的 Arc（COW）
    tiles: Vec<Arc<RgbaImage>>,
    state: Vec<TileState>,
    /// 瓦片 → 与该瓦片相交的图层下标（按 z 序，加载时建一次）
    index: Vec<Vec<u16>>,
    /// 瓦片 → 最高的「完全遮挡下方」的层下标（可选，P2）
    occluder: Vec<Option<u16>>,
}
```

关键点：

- `base` 直接复用现有 `Calibration.reference`（保真态 Document 的 layers[0]），**不额外解一次文件**；
- 自动化（任何 `--` 参数）走的是 `load_path_sync`：它同步装配完整分层栈、**把合并图丢掉了**
  （`fidelityMode`/`hasPsdLayers` 全置 false）。瓦片方案要在探针里可测，`Session::open` 必须
  把阶段 1 的合并图一并留下（**+5.1 MB/文档**），否则「打开 → 全瓦片 == PS」这条断言没法验；
- 未编辑瓦片不复制像素，`tiles[i]` 就是 `base` 的一个子块视图（或懒复制，见实现备注）；
- `index` 在装配时用层 bbox 建：324 个瓦片 × 平均 29 层 = 9.4k 条 `u16`，**约 19 KB**，可忽略。

### 3.3 脏矩形从哪来

现在编辑链路里完全没有"脏区"概念，`EditOp` 只有语义。补一个不侵入的方法：

```rust
impl EditOp {

    pub fn dirty_rect(&self, doc: &Document) -> Option<Rect>;

```

| 操作 | 脏矩形 |
| --- | --- |
| 画笔 / 橡皮 / 涂抹 / 修复 / 修补 | 笔画 bbox（`stroke_mask` 已有 bounds） |
| 图层移动 / 缩放 / 旋转 | 变换前 bbox ∪ 变换后 bbox |
| 不透明度 / 混合模式 / 填充 / 显隐 / 锁定 | 该层 bbox |
| 新建 / 删除 / 复制 / 合并 / 重排 | 受影响图层的 bbox 并集（保守） |
| 调整（亮度/对比度/色相）面板 | 目标作用范围（整层或选区） |
| 调整层参数（未来） | 被作用层的 bbox 并集 |
| 画布裁剪 / 旋转 90° | 整幅（清空账本，回到全量重建一次） |
| 撤销 / 重做 | 该历史项自己的脏矩形（`EditOp` 直接带） |

### 3.4 重合成内核

```rust
impl FidelityView {
    /// 只重合成 rect 覆盖的瓦片。
    pub fn patch(&mut self, doc: &Document, rect: Rect) -> PatchStats {
        let mut stats = PatchStats::default();
        for tile in self.grid.tiles_of(rect) {
            let trect = self.grid.rect_of(tile, doc.canvas);   // 瓦片 ∩ 画布
            let list = &self.index[tile];

            // ① 遮挡裁剪：从最高的"完全不透明覆盖本块"的层开始
            let start = self.occluder[tile].map(|i| i as usize).unwrap_or(0);
            // ② 前缀缓存（P2）：从最近的断点开始，复用 acc 的初始内容
            let (mut acc, from) = self.resume(tile, start);

            for &i in &list[from..] {
                let layer = &doc.layers[i as usize];
                if !layer.visible || layer.opacity <= 0.0 { continue; }
                blend_layer_into(&mut acc, layer, trect);      // 蒙版/剪贴见 P0
            }

            self.tiles[tile] = Arc::new(acc.finish());        // ★只在这里量化到 u8
            self.state[tile] = TileState::Rebuilt { epoch: doc.edit_epoch };
            stats.tiles += 1;
        }
        stats
    }
}
```

三点与现有代码的差别，正是"保真"的来源：

1. **累积缓冲用 `f32`（或 `u16`）**，整块算完再量化一次。现在 `blend_pixel` 每层 `round` 到 u8，33 层堆叠下来是随机游走 1–2/255 的误差，且会随层序变化跳变。
2. **起点可跳过**：`occluder` 记录"这一块最高的不透明层"，它下面的层不必参与（photocraft 的 `occludes_below` 就是这个判据）。
3. **前缀缓存**：瓦片内按层序存若干"安全断点"的累积结果，编辑第 i 层时从 ≤ i 的最近断点恢复，只算断点之上 —— 这才是"改上层几乎零成本"。

### 3.5 成本模型（本文件实测换算）

折算基准：全幅 124 ms / 41.9 Mpx ≈ **2.96 µs / 千像素**（debug，单线程，图层 bbox 裁剪已生效）。

| tile | 块数 | 单块 p50 | 单块 p95 | 单块 max | 200×200 笔刷（4–9 块） |
| --- | --- | --- | --- | --- | --- |
| 32 | 1296 | 0.06 ms | 0.29 ms | 0.31 ms | 0.3–2.6 ms |
| **64** | **324** | **0.22 ms** | **1.16 ms** | **1.22 ms** | **0.9–10 ms** |
| 128 | 84 | 0.94 ms | 4.68 ms | 4.74 ms | 3.8–42 ms |
| 256 | 21 | 4.74 ms | 16.5 ms | 17.5 ms | 19–148 ms |

选 **64 px**：p95 单块 1.16 ms，大笔刷也在 10 ms 内；324 块的拼装是 324 次 `copy_from_slice`（合计 5.1 MB），不到 2 ms。

对照现状：同一笔刷 = 124 ms 合成 + 130 ms 落盘 ≈ **258 ms/帧**（约 3.9 fps）→ 瓦片方案 ≈ **10 ms/帧**（含拼装），**20× 以上**，且未编辑区域完全不参与。

内存增量：`base` 5.1 MB（已在）+ 工作瓦片 5.1 MB + 账本/index 约 0.2 MB ⇒ **+10 MB 量级**。

### 3.6 保真护栏

1. **接缝门限**：脏瓦片重建后与 PS 合并图逐块比对，`MAE ≤ 2 且 p99 ≤ 8` 才算"可用"。超过就打 `Risk` 标记（见下）。
2. **Risk 标记**：块里含当前实现无法精确复现的特性（P0 之前：任何 clip/mask 层；P0 之后：斜面浮雕/图案叠加/未支持调整层）时，该块记 `Risk`。用户在**没编辑**它时看到的仍是 PS 像素（完美保真）；一旦编辑命中，状态栏提示"该区域含 X 特性，已按近似重建"。
3. **回到保真**：撤销到打开时的状态（`edit_epoch == 0` 且历史为空）时，所有瓦片复位 `Pristine`，画面重新逐字节等于 PS —— 补上现在 calibration "sticky 失效后永不回来"的遗憾。
4. **接缝自检探针**：编辑命中瓦片后，检查其**相邻未编辑瓦片**边界 1px 带的差值，> 3/255 就报告（说明合成器有系统性偏差，不是内容差异）。

### 3.7 与现有 calibration 的关系

现在的 `Calibration`（`crates/ui/src/bridge/session.rs:723`）做的是"整幅二选一"：未编辑 → 整幅 PS 合并图；一旦编辑 → 整幅换成重建（sticky）。本方案是把它**降级成"逐瓦片选择"**：

| | 现在 | 改造后 |
| --- | --- | --- |
| 未编辑 | 整幅 PS 像素 | 未编辑瓦片 = PS 像素（其余 = 重建） |
| 第一次编辑 | 整幅重建（sticky，不可逆） | 只有命中瓦片重建 |
| 撤销回原位 | 仍显示重建（sticky） | 复位成 PS 像素 |
| 显示成本 | 1 层 / 8 ms | 未编辑区 1 层；编辑区 O(块) |

`Calibration.reference` 继续存在，作为 `FidelityView.base` 的来源，改动是"从整幅开关变成瓦片账本"，不推翻现有语义。

| 项 | 改动 |
| --- | --- |
| 读图层蒙版 | vendor `LayerRecord` 解析蒙版块（矩形 + `default_color` + disabled 位），`PsdLayer::mask_rect()`；`psd_layers.rs::decode_mask` 按**蒙版自己的矩形**展开 `-2` 通道，裁剪到画布，写进 `PsdLayerData.mask` |
| 读剪贴标记 | `layer.is_clipping_mask()` → `PsdLayerData.clipping`（原来只用于调整层作用域） |
| 文档模型 | `Layer` 增加 `mask: Option<LayerMask { image, offset, default }>` 与 `clipping: bool` |
| 合成 | `Document::flatten`：① 每层 alpha ×= 蒙版取样（矩形外取 `default`）；② 剪贴层 alpha ×= 下方最近非剪贴层的 alpha 覆盖率（覆盖率取该层自己的 alpha × 蒙版，不含样式与不透明度）；③ 累积缓冲 f32，整幅量化一次 |
| 量化 | `blend.rs::blend_pixel_f32`（不 round），`flatten` 走它；标记仍走"物化成图再直绘"（马赛克要读已合成画面） |
| 验收 | `cargo test` 补 4 条语义单测（蒙版遮罩 / 剪贴边界 / 隐藏基底 / 剪贴链共享基底）+ 2 条解码单测（蒙版自带矩形、无蒙版不长出空蒙版）；`psd_fidelity_report.py` 出 MAE 与归因 |

#### 4.2 与原计划的偏差（照实记）

1. **剪贴单元没有用临时缓冲**：计划里写的是"单元内先按 Normal 叠进临时缓冲，
   再整体乘 base alpha"。实现改成**逐层把 alpha 乘上 base 覆盖率**再正常混合。
   对 Normal 层等价；对 Multiply 等非 Normal 层，差别是"与整幅背景混合"还是
   "与剪贴单元内部混合"。实测这一步是净收益，先按简单版落地，差异留给 P1
   的单元化重写。
2. **组蒙版（9 个）没做**：`lsdk` 块还没解析，目标文件里全是穿透组，影响小。
3. **蒙版 / 剪贴暂不写回 PSD**：保存后状态栏会明确写「N 个图层蒙版、M 个剪贴层
   暂未写回 PSD」，避免用户以为存完还在。写回需要 `-2` 通道 + 蒙版块编码 +
   每层 clip 标志位，放进 P1。
4. **vendor 的一个真 bug**：RLE 通道的行长度表一律按**图层高度**剥，而蒙版通道
   是按**蒙版矩形高度**压缩的。结果 108 个蒙版里 34 个（非调整层）解出来是全零，
   剩下的直接判"数据不足"丢弃。已改成按通道种类取行数 —— 这条如果不修，
   蒙版功能等于没做。

### P0.5 — 样式渲染精度（2026-11-13，已完成可测部分）

> 目标：把「合成语义对了但画面还差」的那一段误差压下去。**实测 9.24 → 9.18**，
> 差 >8 的像素 11.43% → 11.38%，最差 32px 块 **114.6 → 73.8**（局部明显变准），
> 但 >32 的像素占比 6.72% → 7.32%（见下面「仍未解决」，有一处局部反例）。
> 首帧 3.25 s 不变。

改的是**几何**，不是"要不要烘焙"。四处取值以前是"看起来差不多"，但它们作用在
几百个图层上，错一点就是整片偏一个方向：

| 项 | 原来 | 现在 | 依据 |
| --- | --- | --- | --- |
| 阴影方向 | `(+cos, +sin)` | `(−cos, +sin)` | PS 角度自 +x 轴逆时针、+y 向上，阴影背离光源；120°/5px 默认落在右下。原式 x 取反 ⇒ **所有投影左右镜像** |
| 内阴影 | 反向位移（`−dx,−dy`） | 与投影同向移动"洞" | 光从上方时内阴影应在**上**边缘内侧；原来画在下边缘 |
| 线性渐变长度 | 包围盒在角度上的投影 | **弦长** `min(w/\|cos\|, h/\|sin\|)` | PS 的 100% 渐变正好铺满包围盒沿角度的弦；60×12 的层在 45° 上两者差 3 倍 |
| 渐变基准 | 内容墨迹包围盒 | 图层矩形 | `Algn` 对齐的是图层矩形 |
| 软衰减 | 三次盒式 ≈ σ=size/2 的高斯 | **两个宽度 size 的盒式（帐篷）** | photocraft 在 psd-tools 语料上与 PS 渲染拟合：阴影覆盖误差 0.0064 → 0.0038 |
| spread/choke | 无（内阴影是"距离阈值内抬到 0.5"） | 先按 `size×spread` 取整膨胀，再以 `size×(1−spread)` 模糊 | PS 的 Size 拆成 spread + blur |
| 距离场 | 3×3 chamfer（布尔掩码） | **5×5 chamfer（步长 1、√2、√5）+ 按 alpha 亚像素播种** | PS 的描边拐角测得 3.236/3.650，3×3 会说 4/4.24；3×3 的等值线是多边形，宽描边露棱 |
| 描边覆盖率 | 形状内一律跳过 | 边界像素按 `1−alpha` 只占"外侧那一份" | 轮廓穿过半透明边界像素，整格跳过会让所有外描边系统性变薄 |

逐项消融（`IMAGEEDIT_FX_LEGACY=<轴>`，只有该轴回退到旧实现）：

| 回退 | MAE | 差 >8 | 差 >32 | 读法 |
| --- | --- | --- | --- | --- |
| 无（全开） | **9.18** | 11.38% | 7.32% | — |
| `dir` | 9.98 | 11.62% | 7.79% | 方向修正 **−0.80**，最大单笔 |
| `dist` | 10.14 | 11.46% | 7.65% | 5×5 + 亚像素 **−0.49** |
| `blur` | 9.69 | 11.52% | 7.57% | 帐篷核 **−0.04**（小，但方向一致） |
| `grad` | 9.65 | 11.32% | 7.55% | 本文件这 94 个渐变叠加都在接近正方形的按钮上，弦长≈投影 ⇒ 量不出差别 |
| `bounds` | 9.65 | 11.39% | 7.55% | 同上：图层矩形与墨迹包围盒基本重合 |
| `all`（全旧） | 10.51 | 11.73% | 7.91% | 四项合计 −1.33 |

另外两条实测：

- **同类多重样式**：`IMAGEEDIT_FX_MODE` 四种展开顺序重测（渲染器已换），
  `first 9.18 | reverse 9.33 | file 9.55 | last 9.66 | off 9.87` —— 仍然取
  **顶条**。文件里 148 个图层有同类叠加（9 个图层 4 个投影、57 个多重描边），
  多出来的基本都是被覆盖的旧草稿，全画反而累积误差。
- **调整层作用域**：剪贴调整层是"整条剪贴链 + 基底"还是"只作用下方一层"，
  `IMAGEEDIT_PSD_ADJUST_SCOPE=chain|last|all` 三种在本文件上 **MAE 完全一致**
  （9.18）；跨组允许与否也一致（`IMAGEEDIT_PSD_ADJUST_CROSS_GROUP=1`）。
  说明本文件的调整层都落在自己组内。仍保留**组边界钳制**（组在 PS 里是独立
  合成单元，跨组必然是 bug），并给调整层补上了它自己的蒙版（按覆盖率插值；
  无蒙版走原快路径，首帧不变）。

#### 仍未解决（照实记）

1. ~~**底部一条横向带状残差**~~ **已在本轮 P0.6 修掉**（9.18 → 8.47）。当时的定性是
   「扁平烘焙模型 vs PS 调整层链式作用」，实测更准确的原因不是链式作用，而是
   **样式像素本来就不该被剪贴调整层改**（见 P0.6）。保留下面的复现配方，它仍然
   是查这类问题的标准动作：
   ```text
   IMAGEEDIT_PSD_DUMP_FX="图层 567"     打印该层解析到的样式参数
   IMAGEEDIT_FX_TRACE="30,88"           打印该缓冲像素的每次样式合成与最终值
   --script=dump-layer:374,tmp/L.png    导出单层位图，与 psd-tools 的 topil() 比
   --script=layer-list                  图层下标/名字/尺寸/offset 全清单
   ```
2. **蒙版整体仍是轻微负收益**：`IMAGEEDIT_PSD_NO_MASKS=1` → 9.13（比开着的 9.18
   更好）。22 个可见带蒙版图层、面积小是一部分原因，但符号一致为负，说明应用
   方式还有偏差（PS 的蒙版同时约束样式与不透明度，我们只乘 alpha）。下一步应
   拿单个带蒙版图层做逐层对照，而不是继续按块归因。
3. **调整层无法真正"逐级链式"**：扁平模型里只能把效果烘进像素，PS 是调整层
   依次作用于下方合成结果。中间隔着别的调整层时必然有差，这是架构性残差。
4. 图案叠加、斜面和浮雕仍不支持（本文件 805 个样式里没有这两类）。

### P0.6 — 剪贴调整层不吃样式像素（2026-11-13，已完成）

> **实测 9.18 → 8.47**，差 >8 的像素 11.38% → 11.23%，差 >32 的 7.32% → 7.08%。
> 首帧 3834 → 4017 ms（+4.8%，同一台机同一次会话内前后对照），内存 +约 12 MB
> （每层一张 1 字节/像素的内容平面）。

上一节「仍未解决 1」那条洋红带状残差，本轮定位并修掉了。

**怎么定位的**（这套路径可以照抄给下一个残差）：

1. `IMAGEEDIT_PSD_NO_ADJUST=1` 与默认各导一次 `dump-flat` 逐像素相减：**全部**差异
   落在 y 1402–1502、x 24–721 一条，正好是「底部按钮」组的 bbox ⇒ 问题不在渲染，
   在调整层烘焙。
2. 该行内逐像素看：`(300,1488)` 关掉调整层时是 `[74,6,33]`，与 PS 参考**逐值相同**；
   打开就变 `[241,12,253]`（洋红）⇒ 某一个调整层把不该改的像素改了。
3. 新加的 `IMAGEEDIT_PSD_TRACE_ADJUST=1` 打印 73 个调整层各自的作用域，命中的是
   `色相/饱和度 570`（父组「提示」，`clip=true`，`start=367,len=368`）——**唯一目标
   就是「图层 567」自己**，作用域没算错。
4. `IMAGEEDIT_PSD_DUMP_FX="图层 567"` 给出它的样式：`Stroke 3px Inside #4a0621`
   ⇒ 洋红那圈原本是**内描边**，落在内容 alpha 里面，所以"按内容 alpha 限幅"还不够。

**结论（PS 语义）**：图层样式是合成期叠在内容之上的**独立一遍**。剪贴到某层的
调整层只改该层的**内容**像素，改不动它自己的样式——所以同一张按钮位图里，填充
被色相改成了黄色、描边仍然是原色 `#4a0621`。烘焙把"内容"和"样式"拍平成一张位图，
这条边界就丢了。

**实现**：

| 位置 | 改动 |
| --- | --- |
| `psd_effects.rs` | `bake` 额外返回 `effect_coverage`（0–255/像素）。`composite()` 是**所有**样式的唯一出口，在那里累加（`1-(1-a)(1-b)` 取并集）；内容那一步直接写 `out`、不走 `composite`，天然不会被记进来。用线程内暂存区传这个平面，省得给 8 个 `draw_*` 都加参数 |
| `psd_layers.rs` | 新增 `ContentAlpha`：`烘焙前 alpha × (1 − effect_coverage)`，**带自己的矩形**（烘焙会为外描边/投影扩边）。`PsdLayerData.content_alpha` 只在有样式时保存 |
| 应用 | `apply_adjustment` 对**剪贴**调整层逐像素乘这个平面；非剪贴（作用于整条链）不乘 |

**验证**：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| MAE（整幅） | 9.183 | **8.466** |
| 差 >8 / >32 | 11.38% / 7.32% | 11.23% / 7.08% |
| `(300,1488)` 描边像素 | `[241,12,253]`（洋红） | `[74,6,33]`（与参考逐值相同） |
| 底部按钮行 MAE | 37.5（>32 31.8%） | **25.2（>32 27.5%）** |
| 首帧 `shown_ms` | 3834 | 4017 |

关掉这条规则的开关是 `IMAGEEDIT_PSD_ADJUST_FULL_ALPHA=1`（回到 9.183），单测
`coverage_marks_the_pixels_the_styles_painted` 锁定「内描边外圈记 255、内部记 0」。

**踩的坑**：第一版把烘焙**前**的 alpha 按烘焙**后**的尺寸取下标，直接越界 panic，
整个 PSD 退化到「合并预览」——而 `dump-flat` 此时导出的正是 PS 的合并图，
**MAE 报 0.000**。所以：看到保真度突然变成 0 或 `layers=1`，先怀疑是不是没加载，
不要庆祝。

**残差热点**（P0.7 之前）：`(704,1248)` 73.8、`(704,1280)` 66.1、`(160,1248)` 60.9
（参考 `[209,164,212]` 浅紫 / `[156,23,26]` 暗红，我们偏白）。这些块不在调整层
作用范围内（关调整层不变），**P0.7 查明是矢量形状层没有像素导致整圈渐变描边
丢失**。


### P0.7 — 矢量形状填充（形状层的像素不在通道里，2026-11-13）

> **实测 8.466 → 7.272**。差 >32 的像素 7.08% → 6.61%；差 >8 的 11.23% → 11.68%
> （**略升**：新画出来的形状边界比原来"什么都没有"更锐利，抗锯齿差异被计入）。
> 首帧 3834 → 3923 ms（+2.3%），`decode_ms` 79。

**问题**：形状图层（`矩形 670` 这类）的**通道数据全是透明的** —— 像素由
Photoshop 按矢量路径实时生成。只读通道时这类层是一片空白，它的描边、内阴影、
渐变叠加也就全部无从谈起。目标稿里有 **5 个**这样的层（全是 153×153 的卡片，
其中一个被画布裁到 22×153），占画布 9.2%，却贡献了 **31% 的总误差**：
卡片外那圈 5px 米黄 + 7px 暗红的渐变描边整圈丢失，是全图最差的四个 32px 块。

| 位置 | 改动 |
| --- | --- |
| `vendor/psd/src/vector.rs`（新） | 解析 `vmsk`/`vsms`（路径）与 `vscg`（填充）。路径记录：`u32 version=3` + `u32 flags`（bit0=反相）+ 记录序列（selector `0/3` 子路径长度、`1/2/4/5` 节点、`6/7/8` 各 24 字节固定块），节点是 6 个 8.24 定点数，y 在前 |
| `vendor/psd/.../mod.rs` | 新增三个 key 的分支；`LayerRecord` / `LayerProperties` 带上 `vector_mask` / `vector_fill` |
| `crates/decode/src/psd_vector.rs`（新） | 贝塞尔展直 + 扫描线（非零环绕、每行 4 条子扫描线、横向解析覆盖率）；填充取 `vscg` 的纯色或渐变（渐变基准 = 路径包围盒） |
| `crates/decode/src/psd_layers.rs` | 位图 alpha 全 0 且带 `vmsk` 时才栅格化（有位图说明缓存里已有渲染结果，再填一遍会盖掉它） |

**解析偏移踩的坑**：填充规则 / 剪贴板 / 初始填充规则这三类记录的负载是固定的
**24 字节**（selector 另算），按 22 字节跳过会让后面整段错位 —— 一条路径都读
不出来，而且不报错（只是"没有矢量蒙版"）。定位靠 `IMAGEEDIT_PSD_VECTOR_TRACE=1`
打印不出任何 `vector-fill` 事件。规范里"24 字节含 2 字节子类型"的说法很容易
被误读成"再跳 22"。

**坐标尺度也是个坑**：路径点名义上是 8.24 定点像素，但**不同导出器单位不同**。
PS 原生文件写的是画布像素（几十到几千），本仓库这份素材写的是 0..1 的比例
（实测包围盒 0.73..0.94）。用固定缩放会把整张卡片画成一个像素的亮点，所以按
数值范围判断：全部点都在 ±4 以内就乘以画布宽高。

**顺带修掉的一个更普遍的 bug**：`FrFX` 的填充分派枚举是 `PntT = SClr | GrFl |
Pttr`，vendor 里却按 `GRad`/`Ptrn` 匹配（那是渐变叠加的写法）。结果是**文件里
每一个渐变描边都被当成纯色**画成土黄 `#bb7b0f`（`(546,1310)` 实测 `[187,123,15]`）。
这一步单独把 MAE 从 8.47 推到 9.14（比不画还差），修正后才落到 8.00。这类
"枚举拼错、静默走 fallback"的错只能靠逐像素比对抓。

**多重样式的顺序要跟着改**：一张卡片有**两条**描边（5px 米黄在上、7px 暗红在
下），`IMAGEEDIT_FX_MODE=first` 只取一条，永远少一圈。四种组合实测：

| 配置 | MAE | >8 | >32 |
| --- | --- | --- | --- |
| `first` + 无矢量（P0.6 基线） | 8.466 | 11.23% | 7.08% |
| `first` + 矢量 | 8.002 | 12.05% | 7.03% |
| `reverse` + 无矢量 | 8.277 | 11.19% | 6.98% |
| **`reverse` + 矢量（新默认）** | **7.272** | 11.68% | **6.61%** |

⇒ 矢量填充单独 −0.46，顺序单独 −0.19，两者一起 −1.19（超可加）：两圈描边既要
形状 alpha 才能画出来，也要顺序对才叠得对。默认已改成 `reverse`（文件里靠前的
条目最后画 = Photoshop 的堆叠顺序），`IMAGEEDIT_FX_MODE=first` 仍可回退。

**没做 / 边界**：开放子路径（只对描边有意义，本文件没有）、奇偶填充规则（一律
非零环绕，PS 默认）、`vstk`（矢量描边内容 —— 本文件的描边都在图层样式里）、
图案填充。写回 PSD 时这些形状层现在会带上栅格化的像素（体积变大，视觉无损：
PS 仍按 `vmsk` 渲染）。

### P2 — 前缀缓存 / 遮挡裁剪（大文件才需要）

- 每瓦片存"完全不透明断点"：`occluder[tile]` = 最高的一层 `visible && opacity=1 && blend=Normal && 无蒙版/样式/剪贴 && 不透明覆盖整块`（photocraft `compose::occludes_below`）。本文件有 7 个层覆盖 > 50% 画布，背景层不透明 ⇒ 大部分瓦片能砍掉下面几十层。
- 每瓦片按层序存 1–2 个累积断点（`Vec<(u16, Arc<RgbaImage>)>`，只对"改上层"的高频操作有价值）。参考 `photocraft/docs/gpu-composite-reuse.md` 的"chunk grid + 前缀复用 + 失效判定"。
- 验收：在本文件上，**只改最上层**时单块 patch ≤ 0.2 ms；`probe_psd_perf.py --check` 的门槛全部不变。

### P3 — 预览链路去落盘（现在每帧 130 ms 在这）

现状：每帧把整幅编码成 BMP（5.1 MB）写临时文件，QML `Image.source` 换 URL 重新解码（`session.rs:1170-1200`）。改造：

- 优先：`QQuickImageProvider` 直接给 `QImage`（零落盘、零解码），或 `QQuickWindow::updateTexture` 类共享内存路径；
- 次选：只对被编辑的矩形区域重编码，QML 侧用「底层整幅图 + 若干瓦片图层」叠加（改动小，但要处理双缓冲一致性）；
- 目标：单帧提交 ≤ 15 ms（debug），2560×1440 预览不掉帧。

## 7. 不承诺的边界

- **不承诺"任何 PSD 都逐像素一致"**。能做到的是：① 没被编辑的像素逐字节等于 PS；② 被编辑的瓦片与 PS 的差在门限内（P0 之后 MAE ≤ 2）；③ 做不到时明确告诉你哪块、因为什么特性。
- **不把"重算"当成保真手段**。PS 的排版/矢量/智能对象渲染是闭源引擎，追平它没有终点；用合并图当锚点才是有限成本。
- **不做无损往返的假承诺**：写回 PSD 时样式/调整层已经被烘焙（这是现状的既定策略，doc `PSD分层可编辑-B方案.md` §19.6 已列），改造后依然如此，直到 P4 做 live 样式。
- **性能数字是 debug 构建**。release 会快 3–5×，但**相对关系**（脏块 vs 全幅）不变，验收门槛按 debug 定，留余量。
